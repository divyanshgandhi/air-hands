# AirHands — Design

**Date:** 2026-07-02 · **Status:** v0.1 built (scope: full gesture engine ·
strategy: Swift-first port · targets: macOS 13+, iOS 16+)

## What this is

An open-source Swift package that turns camera hand tracking into
**instrument-grade gesture events**: velocity-sensitive strikes, holds,
releases, and strums. Extracted from the air-music project, where the same
engine (TypeScript reference implementation) drives a playable piano, drums,
koto, and handpan on the web.

The differentiated part is not landmark acquisition — every platform gives you
21 hand joints. It's what happens after: filtering, per-finger velocity, and
the state machines that decide *this downward flick was a strike at 0.72
velocity* while hovering and drifting stay silent.

## Architecture

```
AirHandsCore   (pure Swift, zero platform deps — the ported engine)
  OneEuroFilter        adaptive smoothing (Casiez et al.)
  FingertipTracker     filtered position + raw-derived velocity per finger
  ZoneIndex            layered hit zones, hysteresis inflation
  StrikeFSM            IDLE → DESCENT → strike → HELD → release
  StrumDetector        fast horizontal sweep = glissando across zones
  GestureSession       wires a HandPoseSource to the engine; latency profiles
  HandPoseSource       protocol: ([RawFingertip], timestampMs) frames

AirHandsVision (Apple adapter)
  VisionHandPoseSource AVFoundation camera → VNDetectHumanHandPoseRequest
                       → mirrored, normalized fingertips (macOS + iOS)

ConformanceKit + airhands-conformance
  Golden-vector replay; the CLI works on Command Line Tools-only machines
  (no XCTest / Swift Testing there); the guarded test target wraps the same
  runner for Xcode environments.
```

## Cross-implementation parity: golden vectors

The TS reference exports JSON conformance vectors (frame sequences + the exact
event streams the engine emitted): 8 StrikeFSM scenarios, 5 strum scenarios,
3 One Euro sequences. `Tests/AirHandsCoreTests/Vectors/*.json`, regenerated by
`air-music/scripts/export-gesture-vectors.ts`. Any port must reproduce them —
events field-by-field, velocities to 1e-9, filter outputs to 1e-12. This keeps
"the feel" identical across languages and makes contributions safe.

Determinism notes for porters: velocities are IEEE-754 doubles produced by the
same arithmetic; event order within a frame is normalized by sorting on
(frame, fingerId, zoneId) before comparison, so hash-map iteration order never
matters.

## Latency profiles

Instead of exposing six thresholds, `GestureSession` ships three profiles —
`.crisp`, `.balanced`, `.stable` — trading strike-confirmation latency
(`maxDescentMs`) and smoothing lag (`minCutoff`) against jitter. Raw configs
stay public and live-tunable for anyone who wants the dials.

## Out of scope for v0.1

visionOS/ARKit adapter (roadmap; contribution target), demo app, Android/
Kotlin port, MIDI output. The vector suite is designed so a future Rust
unification (single core, uniffi bindings) stays cheap.
